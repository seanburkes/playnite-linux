## Residuals and explicit scope boundaries

1. **Add-on store and online catalogue remain v1.1.** p6-010 delivered manifest validation and a
   directory install/uninstall model only; no network, download, update or package-execution path
   is accepted here.
2. **Theme installation/discovery remains deferred.** v10 uses
   `<Themes>/<Mode>/<id>/theme.yaml` with non-recursive discovery; p6-010's extension-root model
   does not implement it.
3. **Plugin UI extension points remain unfrozen** until the Phase 7 shell pilot, per ADR-023.
   p6-009's headless preview types are explicitly unfrozen.
4. **Add-on discovery file-type hardening is a Phase 7 prerequisite.** The p6-010 installer
   rejects FIFO package entries and a FIFO `extension.yaml`, but `AddonInstallLayout.GetInstalled`
   reads manifests found directly in the extensions data tree with `File.ReadAllText` and does not
   use `IRegularFileProbe`. A planted FIFO in that tree could block discovery. Discovery is not
   yet wired into startup; before `p7-001` wires it into boot/DI, it must reject non-regular
   manifest entries or perform a bounded read. This residual is not one of the four P6 exit
   criteria and is not claimed fixed by this acceptance.
5. **Review independence.** As recorded under ADR-024, agent reviews are adversarial assistance,
   not independent human approval. The captain owns this acceptance and the remaining risk of
   correlated blind spots.

These boundaries do not invalidate the four Phase 6 criteria; they remain explicit work or scope
limits for subsequent phases.
