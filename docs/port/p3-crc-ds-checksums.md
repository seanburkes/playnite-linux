# p3-crc-ds — CRC and checksum helpers

## Placement and surface

All product code lives in `Playnite.Core`, namespace `Playnite`. Core remains Avalonia-free and
adds no dependency: the CRC table and the BCL hash algorithms replace the `Crc32.NET` package
v10 pinned. References are relative to `legacy/source/`. The caller column names a legacy
production caller, not only an oracle test.

| Ported surface | Frozen implementation | Real caller |
| --- | --- | --- |
| `Crc32.Append(uint, ReadOnlySpan<byte>)`, `Crc32.Compute(ReadOnlySpan<byte>)` | `Force.Crc32.Crc32Algorithm.Append` as used by `Playnite/Common/FileSystem_Checksum.cs:23` | `Playnite/Emulators/Scanner.cs:1051,1059,1065` |
| `Checksums.GetCRC32(Stream)` | `Playnite/Common/FileSystem_Checksum.cs:16-27` | `Playnite/Emulators/Scanner.cs` via the path overload |
| `Checksums.GetCRC32(string)` | same file, lines 29-35 | `Playnite/Emulators/Scanner.cs:1059,1065` |
| `Checksums.GetMD5(Stream)` | same file, lines 37-43 | internal: the `GetMD5(string)` overload |
| `Checksums.GetMD5(string)` | same file, lines 45-51 | `Tools/Playnite.Toolbox/Themes.cs:167,342` |
| `Checksums.GetSHA256(string)` | same file, lines 53-58 | `Playnite/App/Updater.cs:86`; `Playnite/Diagnostic.cs:142-145` |
| `Checksums.AreFileContentsEqual(string, string)` | same file, lines 60-79 | `Playnite.DesktopApp/ViewModels/GameEditViewModelMetadata.cs:140,164,188` |

The CRC is CRC-32/ISO-HDLC: reflected polynomial `0xEDB88320`, initial register all ones,
final complement. v10's `Crc32Algorithm.Append` exposed that same convention through a running
value that starts at zero, so `Append` keeps the complement inside the call and
`Compute(data) == Append(0, data)`. The hex result is the v10 `"{0:X8}"` form: eight uppercase
digits, no separators.

## Behaviour contract

| Input | Result |
| --- | --- |
| Empty stream / empty file / empty `ReadOnlySpan` | `"00000000"` / `0` |
| `"123456789"` | `"CBF43926"` (the published ISO-HDLC check value) |
| Any split of the same bytes across `Append` calls | identical CRC to one pass |
| MD5, SHA-256 | uppercase, separator-free hex, as `BitConverter` produced in v10 |
| Equal-length files | compared by MD5; different lengths are unequal without hashing |
| Null `Stream` | the v10 exception (`NullReferenceException` for both CRC and MD5) |
| Missing file | the BCL exception from opening the file (`FileNotFoundException`) |

## Adaptation rules

* `SHA256.Create()` replaces the obsolete `SHA256CryptoServiceProvider`; the digest is the same
  and the obsolete provider is not needed for parity.
* `Convert.ToHexString` replaces `BitConverter.ToString(...).Replace("-", "")`; both produce
  uppercase hex without separators.
* Hex formatting is invariant; the `X8` format has no culture-dependent digits, and v10's
  culture-sensitive overload produced the same bytes.
* `AreFileContentsEqual` keeps v10's order: length first, then MD5 of both files. A missing path
  therefore fails at the length check, before either hash is computed.
* The private CRC loop already inlined in `Playnite.Core/Backup.cs` is left untouched: it
  validates ZIP entry CRCs during restore and does not change this unit's surface. A later
  archive change may fold it into `Crc32` without changing behaviour.

## Evidence and provenance

`tests/golden/checksums-v10.json` is generated by
`scripts/port/generate_checksum_goldens.py`, which compiles the frozen
`legacy/source/Playnite/Common/FileSystem_Checksum.cs` unchanged against the exact
`Crc32.NET` version pinned by `legacy/source/Playnite/Playnite.csproj` (1.2.0) and runs it on
.NET 11. It never references the port. Each case records:

* `source: "frozen-v10"` — the expectation is what the frozen source returned;
* `cross_check` — an independent CPython `zlib.crc32`/`hashlib` value for the same bytes. The
  generator fails instead of writing the file if the two disagree. `zlib.crc32` is the same
  reflected IEEE polynomial and its published `"123456789"` check value is `0xCBF43926`.
* `v10_test_constant` — for three cases, the literal v10's own `CheckSumTests` asserted for
  `Tests/Playnite.Tests/Resources/TestIni.ini`; the frozen run must reproduce it exactly.

The inputs are empty, the standard vector, `a`, `abc`, a pangram, UTF-8 non-ASCII, all 256 byte
values, a 5000-byte pattern (more than one 4096-byte v10 read), the v10 `TestIni.ini` resource,
a 1 MiB pattern split across `Append` calls in the oracle, and file/stream overload pairs.
`ChecksumTests` also states the published check value and the empty-input value directly, so
the two load-bearing constants do not depend on the golden file alone.

`Frozen_v10_checksum_expectations_match` exercises every golden case and asserts each case's
`source`, `cross_check` and (when present) `v10_test_constant` against `expected`, so editing a
single expectation in the golden fails instead of passing silently. Additional tests cover
incremental composition at every boundary of a sentence, a 1 MiB buffer split into 1, 2, 4095,
4096, 4097, 65536 and 100000 byte updates against one pass, and agreement between the stream
and path overloads.

Regenerate outside the checkout and review the diff; there is no auto-accept command:

```sh
python3 scripts/port/generate_checksum_goldens.py --output <scratch>/checksums-v10.json
```

The golden and the surface-parity row are protected oracle artifacts, so adding them uses the
`oracle-change` route; `legacy/` is untouched.

## Pinned surprises and boundaries

* `Crc32.NET`'s `Append` takes and returns the **final** CRC, not the raw register value. The
  port keeps that shape (`Append(0, empty) == 0`), which is what makes the v10 stream loop and
  the incremental tests agree.
* Null streams throw `NullReferenceException`, not a validated argument error, in both helpers.
  The golden pins the exception identity rather than inventing friendlier validation.
* MD5 remains a legacy comparison/cache key. This unit does not promote it to a security
  primitive, and SHA-256 is available for integrity callers.
* Nothing here is Windows-specific: no path matching, attributes, ACLs or interop.

## Deferred

No surface from the frozen file is deferred. Scanner integration (consuming the CRCs while
building emulator game lists) belongs to the emulator-scanner unit, not this helper unit.
