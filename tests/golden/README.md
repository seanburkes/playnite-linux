# Golden corpus

Generated by oracle runs, not hand-written. Each directory has a provenance note.

## `checksums-v10.json`

Source: `legacy/source/Playnite/Common/FileSystem_Checksum.cs`.

Captured by: `scripts/port/generate_checksum_goldens.py`, which compiles the frozen file on
.NET 11 with the `Crc32.NET` version pinned by `legacy/source/Playnite/Playnite.csproj`
(1.2.0) and runs it. Each case records `source: "frozen-v10"` plus an independent
`zlib.crc32`/`hashlib` cross-check that the generator refuses to disagree with, and the
`"123456789"` check vector is `0xCBF43926`. Three cases also carry `v10_test_constant`, the
literal v10's own `CheckSumTests` asserted for its `TestIni.ini` resource. Regenerate outside
the checkout, review the diff, and put the result in place; there is no auto-accept command.

## `manifests/`

Source: `legacy/source/Tests/TestPlugin/extension.yaml` and
`legacy/source/Tests/TestGameLibrary/extension.yaml`.

Captured by: `.github/workflows/legacy-oracle.yml`, run 43605036209, via
`LegacyOracle manifest <path>` (v10 `ExtensionManifest.FromFile` + v10 YAML serializer).

Regenerate: run the workflow, download the `legacy-oracle` artifact, copy
`tests/golden/manifests/` into place, and review the diff. There is no auto-accept command.

Rules:

- Do not edit these files in a porting change.
- Do not normalise line endings or whitespace when comparing; the bytes are the oracle.
- A new golden needs a provenance note and the `oracle-change` route: the label declares it and
  the protected-path gate checks the diff; review is adversarial on the owner's behalf.
